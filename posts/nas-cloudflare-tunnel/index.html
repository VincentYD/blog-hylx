群晖 NAS + Cloudflare Tunnel：不开端口，把家里 9 个服务安全地搬到外网

2026年11月8日 约 7 分钟 3088 字 人间无事人 NAS 折腾

家里 NAS 上跑了一堆服务：DSM、青龙面板、MoviePilot、三个 qBittorrent、Emby、Transmission、IYUU。以前出门全靠 Tailscale，组网是好用，但总想多留一条后路——万一哪天 Tailscale 抽风，人在外面就什么都摸不到了。

于是花了一个晚上，用 Cloudflare Tunnel 把这 9 个服务都接到了外网。没有开端口，没有公网 IP，没有备案，全程免费。

最后的效果：nas.我的域名 打开就是 DSM，ql.我的域名 是青龙，每个服务全部能从外网打开，并且全部上了 Cloudflare Access，只放我自己的邮箱进，别人连登录页都看不到。

准备工作#

  • 一个 Cloudflare 账号，域名已经接进 Cloudflare（我用的是免费的 .cc.cd 域名，解析走 Cloudflare）
  • 群晖 NAS，装好 Container Manager（Docker）
  • NAS 的局域网 IP：我这里是 192.168.110.168，下面都按这个写，换成你自己的

第一步：在 Cloudflare 后台创建 Tunnel#

步骤：

  1. 打开 Cloudflare 后台 → 左侧 Networking → Tunnels（老版入口在 Zero Trust → Networks → Tunnels 下）
  2. 点 Create a tunnel，填 tunnel name，名字随便起，我起的是 nas，然后点 Create tunnel
  3. 我们看Operating System，也就是你要将服务放到什么系统，我这边是nas，所以我选择docker，下面有一行命令Run tunnel with Docker，复制下来，命令最后面有一串token，这个你记好，等下要用到，这个token只在建 Tunnel 这一次显示，复制下来保存好，后面 compose 文件里要用。Token 别发给别人，也别贴到公开地方。
  4. Connection Status会一直刷新，显示 No connection detected yet——正常，因为 NAS 那边还没跑起来，cloudflare这边前期就好了。

第二步：在群晖上跑 cloudflared#

用 Container Manager 的 Project（docker-compose）方式跑，比直接建容器好管理。

在 Container Manager → 项目 → 新增，项目名 cloudflared，compose 内容如下（Token 换成你自己的那串）：

yaml 
services:
  cloudflared:
    image: cloudflare/cloudflared:latest
    container_name: cloudflared
    restart: unless-stopped
    command: ["tunnel", "--no-autoupdate", "run", "--token", "你的 Tunnel token"]

这里有两个坑，都是我当天真实踩到的：

坑一：command 必须用列表写法。 我第一版写的是字符串形式：

yaml 
command: tunnel --no-autoupdate run --token xxx

结果容器起来后只反复打印 cloudflared 的 help 信息然后重启循环，根本没连上 Cloudflare。改成上面那种 ["tunnel", "--no-autoupdate", "run", "--token", "xxx"] 列表形式才正常。

坑二：改完 compose 文件，光重启容器没用。 群晖 Container Manager 的 Project 是按第一次创建时的配置跑的，改完文件只点重启，不会重新读 compose。必须把项目停止 → 删除 → 重新建项目，改动才生效。

删了重建之后，看容器日志，出现 Registered tunnel connection 之类的连接成功记录，再回 Cloudflare 后台看 Tunnel 状态变成 Healthy，cloudflared 版本显示 2026.10.7，这一步就通了。

第三步：加 Public Hostname（9 条路由）#

Tunnel 通了之后，点开刚刚自己创建的Tunnel（我的名字是nas） → Add route→Published application ，逐个加。Subdomain 填你的子域名，Domain 选你的域名，Service 选 HTTP，URL 填你的 NAS 局域网 IP 加端口，比如 192.168.110.168:5000，前面不用加 http://（Type 选 HTTP 就行，后台会自动补）。

子域名指向服务
nas.你的域名192.168.110.168:5000DSM
ql.你的域名192.168.110.168:5700青龙面板
mp.你的域名192.168.110.168:3000MP
qb.你的域名192.168.110.168:8080qBittorrent
qb1.你的域名192.168.110.168:8081qBittorrent
qb2.你的域名192.168.110.168:8082qBittorrent
emby.你的域名192.168.110.168:8096Emby
tr.你的域名192.168.110.168:9091Transmission
iyuu.你的域名192.168.110.168:8780IYUUPlus

第四步：逐个从外网验证#

加完别急着收工，断开家里 Wi-Fi（或用手机流量），逐个打开验证。我当时的验证结果：

  • nas、ql、mp、qb、qb1、qb2、emby、iyuu：全部返回 200，正常打开
  • tr（Transmission）：返回 401，这是要登录，属于正常，也算通

如果某个打不开，先看两点：Tunnel 是不是 Healthy；Public Hostname 里的 Service 地址和端口对不对。大部分问题都出在这两处。

第五步：上锁——Cloudflare Access 只放自己进#

服务能从外网打开了，下一步必须上锁，不然等于把家里 NAS 的登录页挂在公网上裸奔。

我给 9 个子域名各建了一个 Cloudflare Access 应用，策略就一条：Allow，只放我自己的两个邮箱，登录方式是邮箱验证码（One-time PIN），会话 24 小时。下面是后台手动建的每一步，照着点就行。

5.1 第一次进 Zero Trust：先定团队名#

第一次打开 Zero Trust 会让你先做一次设置，只做一次：

  1. 打开 Cloudflare 后台 → 左侧点 Zero Trust
  2. 选 Free 计划，点 Proceed
  3. 起一个团队名（Team name），这个名字会变成你的登录页域名：团队名.cloudflareaccess.com。我起的是 renjianwushiren，所以我的登录页域名是 renjianwushiren.cloudflareaccess.com。起个自己记得住的就行

5.2 确认邮箱验证码登录方式已启用#

Access 默认的登录方式就是邮箱验证码（One-time PIN），不用接 Google、GitHub 那些，确认一下它在就行：

  1. Zero Trust 左侧 → Settings → Authentication
  2. Login methods 下面确认有 One-time PIN 这一项（默认就是启用的）
  3. 不用改别的，直接下一步

5.3 建第一个应用（以 nas 为例）#

  1. Zero Trust 左侧 → Access controls → Applications
  2. 点 Create new application（有的版本叫 Add an application）
  3. 选 Self-hosted（有的版本叫 Self-hosted and private）
  4. 填这三项：
  • Application name：应用名，只在后台显示，我填的是 nas
  • Session Duration：会话时长，选 24 hours——登录一次，24 小时内再打开不用重新输验证码
  • Application domain：子域名填 nas，域名下拉选你的域名，拼出来就是 nas.你的域名
  1. Identity providers 这一栏保持默认就行，里面已经勾上了 One-time PIN
  2. 先别点保存，往下翻到 Access policies，点 Create new policy，建策略

5.4 建策略：只放自己的两个邮箱#

策略是在应用里顺手建的，不用单独去 Policies 页面：

  1. Policy name：策略名，我起的是 Allow YU
  2. Action：选 Allow（注意 Access 默认是拒绝所有人，必须有一条 Allow 策略才进得去）
  3. Include 规则：点 Add a rule（或 Add include）→ 规则类型选 Emails → 把邮箱一个一个加进去就行。
  4. 其他规则不用加，点保存，策略就挂到这个应用上了
  5. 回到应用页面，点 Save（或 Add application），第一个应用就建好了

5.5 剩下 8 个子域名，重复一遍#

ql、mp、qb、qb1、qb2、emby、tr、iyuu 各建一个应用，步骤和上面完全一样，只有两处不一样：

  • Application name 和 Application domain 换成对应的子域名（比如 ql、ql.你的域名）
  • 策略不用新建，Access policies 那一步选已有的 Allow YU 挂上去就行

9 个建完，Applications 列表里应该有 9 条，每条都挂着 Allow YU。

5.6 验证：每个域名都应该先跳登录页#

建好后逐个验证，方法一样：

  1. 浏览器打开 https://nas.你的域名/（换成你要验的那个子域名）
  2. 应该先 302 跳到 Access 登录页（地址是 renjianwushiren.cloudflareaccess.com 那边），而不是直接看到 DSM 登录页
  3. 输入你的邮箱，收一封验证码邮件，把 6 位验证码输进去
  4. 验证通过后才看到 DSM 登录页；24 小时内再打开这个域名，不用重新输验证码

9 个域名都按这个走一遍，全是先跳登录页、输验证码才能进，就算锁好了。

常见问题#

Q：Tunnel 和 Tailscale 冲突吗？ 不冲突。Tailscale 继续当主力，Tunnel 当备用。两条路走的完全是不同通道，平时用哪个都行。

Q：cloudflared 容器只打印 help，怎么办？ command 改列表写法，然后删项目重建。只重启容器不生效，见第二步的两个坑。

Q：打不开某个服务，先查什么？ 先看 Tunnel 是不是 Healthy，再看 Public Hostname 的 Service 地址是不是 NAS 局域网 IP + 正确端口。tr 返回 401 是正常的，那是 Transmission 本身要登录。

Q：Access 验证码收不到怎么办？ 先看邮箱垃圾箱。验证码 10 分钟过期，过期了重新请求一个就行。

小结#

整个链路就五步：后台建 Tunnel → 群晖跑 cloudflared → 加 9 条路由 → 外网逐个验证 → Access 上锁，照着走应该能一次过。
