青龙面板 + WorkBuddy 自动签到：每天 00:05 自动领 100 积分

2026年11月8日 约 11 分钟 5184 字 人间无事人 NAS 折腾

WorkBuddy 每天签到能领 100 积分，成长中心还有旅行礼物、任务奖励、盲盒这些可以领。每天手动点一次不难，但总有忘记的时候，断签一天连登就得重算。

于是我用一个开源脚本把它全自动化了：每天 00:05 自动签到领 100 积分，每 4 小时轮询一次成长中心，全程零 Token，不经过 AI 模型。

项目地址：https://github.com/88lin/workbuddy-auto-signin

先说结果：2026 年 11 月 7 日那天实测跑通，当天签到成功领了 100 积分（连续 1 天）。青龙上现在两个任务在跑，一个每天 00:05 签到，一个每 4 小时轮询。下面是每一步具体怎么做。

先说清楚：为什么不能直接用仓库的一键安装#

仓库的官方用法很简单：Windows 上一条 PowerShell 命令就装好两个定时任务，macOS 上套个 launchd 模板。但那是给桌面端准备的，我要把它放群晖的青龙面板上跑，情况不一样：

  • 脚本靠读取本机 WorkBuddy 桌面端登录后写出的凭据文件鉴权，NAS 上没有 WorkBuddy 桌面端，拿不到登录态。
  • 青龙容器是 Alpine Linux，没有终端，所有命令都得靠"新建一个临时任务 → 手动执行 → 看日志 → 用完删掉"来跑。
  • 所以整条路是：先在 NAS 上装 CodeBuddy CLI 并登录（Linux 上脚本读的就是它的凭据），再把签到脚本挂到青龙定时任务上。

下面按顺序走，一共五步。

准备工作#

  • 一个 WorkBuddy 账号，已经在 Windows 电脑的 WorkBuddy 桌面端上登录过（登录态要和后面手机登录用同一个腾讯账号）
  • 群晖 NAS，上面跑着青龙面板（我这里是 2.23.0，地址是 192.168.110.168:5700，换成你自己的）
  • 青龙容器里有 Python 3 和 Node.js（我这里是 Python 3.11.17、Node v24.18.1、npm 11.12.1）
  • 仓库地址：https://github.com/88lin/workbuddy-auto-signin

第一步：把 signin.py 传到青龙#

仓库核心就一个 signin.py，单文件、零第三方依赖，只要 Python 3 就能跑。

  1. 先把仓库下到本地：
bash 
git clone https://github.com/88lin/workbuddy-auto-signin.git
cd workbuddy-auto-signin

没装 git 的话，去仓库页面点 Code → Download ZIP 解压，效果一样。

  1. 把 signin.py 传到青龙的脚本区，也就是容器里的 /ql/data/scripts/ 目录。可以在青龙面板 → 脚本管理里新建/上传，也可以用青龙 OpenAPI 传。
  2. 注意一个坑：上传接口除文件外还必须带 filename 字段，不带会报 400。
  3. 传完确认一下，脚本区里应该能看到 signin.py。

第二步：装 CodeBuddy CLI（npm 版）#

这是第一个真坑，花了我最久。

坑一：官方原生二进制在青龙上跑不起来#

CodeBuddy 官方给了一个安装脚本 install-codebuddy.sh，下载的是 Bun 打包的原生二进制。在青龙的 Alpine 容器里跑它会报 ERR_DLOPEN_FAILED，缺 ld-linux-x86-64.so.2——Alpine 用的是 musl，不是 glibc，这条路不通。不要在这上面浪费时间。

正确做法：用 npm 版#

  1. 在青龙里新建一个临时任务，命令填下面这几行（用完删掉，正式任务后面再建）：
bash 
export HOME=/ql/data/codebuddy-home
npm config set prefix "$HOME/.npm-global"
export PATH="$HOME/.npm-global/bin:$PATH"
npm install -g @tencent-ai/codebuddy-code@2.181.0
codebuddy --version
  1. 手动执行这个临时任务，看日志。codebuddy --version 输出 2.181.0，安装就成功了。
  2. 临时任务用完删掉。

这里有两个细节，一个都不能错：

  • HOME 必须指到 /ql/data/codebuddy-home。青龙容器默认 HOME 是 /root，容器一重启就丢了；/ql/data/ 是持久目录，登录态放这里才不会丢。后面所有命令都要先 export HOME=/ql/data/codebuddy-home。
  • npm 全局目录也要放在持久目录里。npm config set prefix "$HOME/.npm-global"，装完 codebuddy 在 $HOME/.npm-global/bin/codebuddy，PATH 里也要加上这一段。

第三步：登录 CodeBuddy CLI（手机扫码）#

这是第二件麻烦事：CodeBuddy CLI 没有独立的登录命令，只能进交互界面输 /login。青龙又没有交互终端，只能用 Python PTY 在后台驱动它。

具体做法#

  1. 在青龙里新建一个临时任务，跑下面这个 PTY 脚本（保存成 /ql/data/scripts/cb-pty-login.py，临时任务里调它）：
python 
#!/usr/bin/env python3
"""用 PTY 驱动 codebuddy，自动走完信任对话框和 /login，拿登录链接。"""
import fcntl, os, pty, select, struct, sys, termios, time

HOME = "/ql/data/codebuddy-home"
CB = os.path.join(HOME, ".npm-global", "bin", "codebuddy")
DUR = 150  # 等 150 秒，够手机上完成登录
RAW = os.path.join(HOME, "login-pty-raw.log")

os.environ["TERM"] = "xterm-256color"
master, slave = pty.openpty()
fcntl.ioctl(slave, termios.TIOCSWINSZ, struct.pack("HHHH", 40, 120, 0, 0))

pid = os.fork()
if pid == 0:
    os.setsid()
    os.dup2(slave, 0); os.dup2(slave, 1); os.dup2(slave, 2)
    os.close(master); os.close(slave)
    os.chdir(HOME)
    os.execv(CB, [CB])
    os._exit(127)

os.close(slave)
out = open(RAW, "wb")
# 时序表：秒数 → 发什么
schedule = [
    (5, b"\r"),        # 回车确认信任文件夹对话框（默认选项 1）
    (9, b"\r"),        # 再回车一次兜底，防止对话框出现得晚
    (14, b"/login\r"), # 触发登录流程
    (20, b"\r"),       # 回车确认默认「中国站」
    (26, b"\r"),       # 再回车一次兜底
]
sent = [False] * len(schedule)
start = time.time()
try:
    while time.time() - start < DUR:
        r, _, _ = select.select([master], [], [], 0.5)
        if r:
            try:
                data = os.read(master, 65536)
            except OSError:
                break
            if not data:
                break
            out.write(data)
        now = time.time() - start
        for i, (t, b) in enumerate(schedule):
            if not sent[i] and now >= t:
                os.write(master, b)
                sent[i] = True
finally:
    out.close()
print("done, raw log:", RAW)
  1. 临时任务的命令填：
bash 
export HOME=/ql/data/codebuddy-home
export PATH="$HOME/.npm-global/bin:$PATH"
python3 /ql/data/scripts/cb-pty-login.py
  1. 手动执行，等一会儿去看任务日志，里面会有一行登录链接。链接约 10 分钟有效，手机上用平时登 WorkBuddy 的那个腾讯账号打开，完成登录。
  2. 登录完成后，检查凭据文件是不是写出来了。凭据在：
CODE 
/ql/data/codebuddy-home/.local/share/CodeBuddyExtension/Data/Public/auth/Tencent-Cloud.coding-copilot.info

我那天是 12:51 写出来的，4505 字节。文件在，登录态就有了。

这一步的两个要点#

  • 回车必须发 CR（\r），不是 LF（\n）。TUI 程序认 CR，管道里 echo '/login' 喂进去是没用的，我试过，不行。
  • 信任文件夹对话框出现得有延迟，所以时序表里 5 秒和 9 秒各回车一次、20 秒和 26 秒各回车一次，都是兜底，别省。

第四步：验证登录态，手动跑一次签到#

登录完了先别急着建定时任务，先验证两件事。

  1. 新建临时任务，跑 doctor 自检（离线检查凭据格式，不解密、不联网）：
bash 
export HOME=/ql/data/codebuddy-home
export PATH="$HOME/.npm-global/bin:$PATH"
cd /ql/data/scripts
python3 signin.py doctor

输出里 result 是 AUTH_READY、凭据格式是 plaintext，就说明凭据可用。

  1. 再手动跑一次完整签到：
bash 
export HOME=/ql/data/codebuddy-home
export PATH="$HOME/.npm-global/bin:$PATH"
cd /ql/data/scripts
python3 signin.py auto

我那天跑完，输出里是 CLAIMED，成功领取 100 积分，连续 1 天、累计 100 积分。看到这个，这条路就通了。

  1. 临时任务用完删掉。

第五步：建青龙定时任务#

坑二：cron 命令里别写 export#

青龙 cron 命令里 export 跨 ; 有时不生效，带管道的段落也拿不到前面 export 的变量（我当初就是这么把 codebuddy 弄丢的）。可靠做法是：环境变量写进脚本文件里，cron 只写 bash 脚本 调用。

包装脚本 workbuddy-run.sh，放在 /ql/data/scripts/，内容如下（就 6 行）：

bash 
#!/usr/bin/env bash
# WorkBuddy 签到脚本包装器：固定 HOME 到持久目录，让 signin.py 找到 CodeBuddy CLI 的凭据文件；
# 经 workbuddy-notify.py 跑，领到东西或出错时走青龙 notify.py 发 Bark。
export HOME=/ql/data/codebuddy-home
export PATH="$HOME/.npm-global/bin:$PATH"
cd /ql/data/scripts || exit 1
python3 /ql/data/scripts/workbuddy-notify.py "$@"

建两个任务#

青龙面板 → 定时任务 → 新建：

任务名定时命令干什么
WorkBuddy每日签到每天 00:05bash /ql/data/scripts/workbuddy-run.sh auto签到 + 成长中心
WorkBuddy成长中心轮询每 4 小时bash /ql/data/scripts/workbuddy-run.sh silent-poll补签（未签才签）+ 成长中心全套

建完先手动执行一次「WorkBuddy每日签到」，看日志确认领到 100 积分，再让它自己跑。

为什么要两个任务#

签到一天一次就够了，成长中心不是：Buddy 出去旅行 1~4 小时就带着礼物回来，礼物得及时领。只靠 00:05 那一次，礼物会压到第二天；万一某天 00:05 没跑成（关机、网络没就绪），连签还会断。

轮询每 4 小时跑一轮，每轮先查一次签到状态，未签才补，已签就只是一个查询请求，不会重复领取。脚本幂等，重复跑也不会多领。等于一天有 7 次机会兜底。

让签到结果推到手机上（Bark 通知）#

signin.py 自己不发通知，跑完只输出一行 JSON——青龙也不会自动给任务发通知。其他签到脚本有通知，是因为它们调了青龙自带的 notify.py，走面板里配好的 Bark。所以包装脚本里多包了一层 workbuddy-notify.py，放在 /ql/data/scripts/，和 signin.py 同目录：

python 
#!/usr/bin/env python3
"""跑 signin.py，领到东西或出错时经青龙自带的 notify.py 发 Bark。

用法（青龙定时任务里调它，不用直接调 signin.py）：
    python3 workbuddy-notify.py auto         # 每天 00:05 那次
    python3 workbuddy-notify.py silent-poll  # 每 4 小时轮询那次

通知规则（避免轮询空跑刷屏）：
  - auto：stdout 就是一行 JSON；result 是 CLAIMED 或 needs_attention 为真才推；
    ALREADY（已签过）不推。
  - silent-poll：结果只写 signin.log，空跑不落盘；日志长了才说明有动静，
    取最后一行里的 report 推。
  - signin.py 退出码非 0（报错）一定推。
  - notify.py 找不到或推送失败时只打印一行警告，不影响签到本身。
"""
import json
import os
import subprocess
import sys

HERE = os.path.dirname(os.path.abspath(__file__))
SIGNIN = os.path.join(HERE, "signin.py")
LOG = os.path.join(HERE, "signin.log")


def log_size():
    try:
        return os.path.getsize(LOG)
    except OSError:
        return 0


def bark(title, content):
    try:
        sys.path.insert(0, HERE)
        from notify import send
        send(title, content)
        print("notify sent")
    except Exception as e:
        print(f"notify failed (sign-in unaffected): {e}")


def parse_report(line):
    """日志行形如 '[2026-08-30 10:34:04] {json}'，取出 JSON 里的 report。"""
    try:
        data = json.loads(line[line.index("{"):])
        return data.get("report", ""), data
    except Exception:
        return line, None


def main():
    action = sys.argv[1] if len(sys.argv) > 1 else "auto"
    before = log_size()
    proc = subprocess.run(
        [sys.executable, SIGNIN, action], capture_output=True, text=True
    )
    out = (proc.stdout or "").strip()
    err = (proc.stderr or "").strip()
    if out:
        print(out)
    if err:
        print(err, file=sys.stderr)

    if proc.returncode != 0:
        bark("WorkBuddy 签到失败", out or err or f"signin.py exited {proc.returncode}")
        return

    # auto：stdout 就是一行 JSON
    if out:
        try:
            data = json.loads(out)
        except json.JSONDecodeError:
            data = None
        if data:
            if data.get("result") == "CLAIMED" or data.get("needs_attention"):
                bark("WorkBuddy 签到", data.get("report", "") or out)
            return

    # silent-poll：结果只写日志，日志长了才说明有动静
    if log_size() > before:
        with open(LOG, encoding="utf-8") as f:
            lines = f.read().strip().splitlines()
        if lines:
            report, _ = parse_report(lines[-1])
            bark("WorkBuddy 签到", report)


if __name__ == "__main__":
    main()

通知规则：领到积分、出错、需要注意时推；已签过、轮询空跑不推，不然每 4 小时刷一条太吵。我实测过，推一次手机上就收到。

成长中心能领什么，领不到是怎么回事#

auto 一轮会跑：领旅行礼物 → 派 Buddy → 领取新任务 → 领任务奖 → 断登自动补登 → 连登奖励兑换 → 开盲盒 → 能量开 Buddy 盲盒。

我实测那天，成长中心多数任务领不到，原因是前置条件 first_buddy 没满足——我还没领养 Buddy。这是账号本身的状态，不是脚本故障。去 WorkBuddy App 里领养一只 Buddy，之后成长任务就能自动领了。

另外两个正常现象，不用慌：

  • 服务端每天只放行一次派出，轮询日志里老是「今日旅行名额已用完」是正常的，第二天自动恢复。
  • 连登兑换分三档，要连登满 7 / 14 / 28 天才解锁，天数不够时服务端返回 403，脚本按常态处理，不记为失败。

登录有效期与续期#

CodeBuddy CLI 的登录不是永久的：

  • accessToken 有效期 30 天，我这次是 2026-12-07 12:51 到期
  • refreshToken 约 60 天，2027-01-06 12:51 到期

到期后签到会失败，续期办法就是把第三步再走一遍：用 PTY 调出 /login 拿链接，手机上登录续上。脚本本身不会刷新 token，只读凭据文件里的 accessToken 发请求。

可选：Qoder CN（青龙这条路不适用）#

同一个仓库还附带一个独立的 qoder_signin.py，自动领 Qoder CN 个人用户每天 100 通用 Credits。每天 10:00（UTC+8）刷新，领完 30 天有效，没有补领，错过当天窗口就没了。

但这条在青龙上走不通：Qoder 的登录态自动读取只支持 Windows 和 macOS，Linux 上读不到，只能手动设 QODER_TOKEN，令牌还会过期，官方不推荐长期保存。所以我这套青龙流程里没接 Qoder。

如果你是在 Windows 上跑：仓库里有 install-qoder-windows.ps1，一键装一个 QoderDailyCredits 任务，每天 10:05 起，另加 11:05 / 15:05 / 19:05 / 23:05 五次触发兜底，领取本身幂等，已领过只会查询。macOS 则是 install-qoder-macos.sh。

常见问题#

Q：跑 doctor 报 NO_AUTH，怎么办？ NAS 上没有登录态。先确认凭据文件在不在：/ql/data/codebuddy-home/.local/share/CodeBuddyExtension/Data/Public/auth/Tencent-Cloud.coding-copilot.info。不在就回第三步重新走一遍 PTY 登录；文件损坏（不是合法 JSON）也一样，重新登录一次就重建了。

Q：00:05 那次失败了，连签是不是断了？ 不一定。轮询任务每 4 小时都会先查签到状态，未签就补上，补签那轮日志会带 "trigger": "poll"。所以 00:05 失败不等于当天断签。

Q：签到结果去哪看？ silent 模式的结果写进 signin.log（和 signin.py 同目录）。轮询任务只有真领到东西或出错时才写日志，「已签过」「Buddy 还在路上」这类空跑不落盘，免得有价值的记录被淹没。想逐轮查看就设 WORKBUDDY_GROWTH_LOG_EMPTY=1。

Q：青龙通知怎么配？ 青龙的 Bark 通知如果用自建服务器，BARK_PUSH 只填设备码会默认发到官方服务器，必须填完整地址：https://你的 Bark 服务器地址/设备码。

Q：Windows / macOS 上跑是不是更简单？ 是。仓库官方就是给桌面端准备的：Windows 上在仓库目录跑一条 powershell -ExecutionPolicy Bypass -File .\install-windows.ps1，两个任务自动建好；macOS 套 workbuddy-auto-signin.plist.example 模板。青龙这套是我为了放 NAS 上自己折腾出来的，步骤多，但跑起来之后就不用管了。

小结#

整条链路就五步：传 signin.py 到青龙 → 装 npm 版 CodeBuddy CLI → 手机扫码登录拿凭据 → doctor 验证 + 手动跑通 → 建两个定时任务。两个真坑：原生二进制在 Alpine 上跑不起来，改走 npm 版；cron 命令里别写 export，环境变量写进包装脚本。

跑通之后每天 00:05 自动领 100 积分，成长中心每 4 小时轮询一次，通知也接上了：领到积分或出错时 Bark 推一条，没事不推。唯一要记的就是登录有效期：accessToken 30 天，到期重新扫码续上就行。
